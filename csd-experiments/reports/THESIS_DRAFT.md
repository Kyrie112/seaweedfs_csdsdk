# 面向可计算存储的分布式文件系统计算下沉方法研究与实现

——以 SeaweedFS + SmartSSD 的近存图像检索为例

## 摘要

数据密集型应用的计算瓶颈正从处理器转移到数据搬运。可计算存储(Computational
Storage)通过把计算能力下移到存储设备内部,使数据在产生位置完成处理,从而减少
主机内存带宽占用与端到端时延。然而,把可计算存储接入一个既有的分布式文件系统
并非简单的接口适配:数据的物理布局、分块策略、副本调度与结果聚合都会随之改变,
其中若干问题会**静默地产生错误结果**,而不表现为崩溃或报错。

本文以开源分布式文件系统 SeaweedFS 与内置 FPGA 的智能固态硬盘 SmartSSD 为平台,
设计并实现了一套完整的计算下沉机制,包括:(1) 基于"区间描述符"的近存计算协议;
(2) 跨数据块的并行编排与结果聚合;(3) 能力感知与负载感知的副本调度;
(4) 基于页缓存感知的自适应数据通路选择。在此基础之上,本文面向以图搜图场景,
设计并实现了近存 Top-K 相似检索算子。

本文的主要理论结果包括两项。**第一**,针对设备端必须按块对齐读取这一约束,
本文形式化定义了算子的**对齐不变性**,证明按字打包类算子具有 8 字节周期的
偏移敏感性,从而**无法在主机侧通过裁剪补偿**,必须将偏移量下推到设备;
并据此给出了算子的分类与接口约束。**第二**,本文证明跨块聚合结果与整文件结果
同余的**充要条件是每个数据块大小均为打包单元的整数倍**,指出并修复了原实现中
"同一文件在单块与多块路径下语义漂移"的缺陷;实验数据佐证了该同余关系
(16 块聚合值与整文件真值之差恰好为 2×2^64)。

在实验方面,本文在本地部署了完整的 master + volume + filer + CSD agent 链路,
并以软件 agent 复现设备语义,完成了正确性与性能验证:冷缓存下对齐直读路径
端到端时延降低 26.8%;自适应通路在缓存命中时加速 6.2 倍,并**发现并解释了
"自适应无法自举"这一负面结论**;以图搜图算子在 1024/4096/16384 张图片的
图库上,返回结果与暴力检索**逐位一致**,端到端时延为传统"下载全库 + 本地检索"
方案的 1/43 ~ 1/93,回传数据量减少 99.999% 以上。

**关键词**:可计算存储;近存计算;FPGA;分布式文件系统;数据下沉;Top-K 检索

## Abstract

The bottleneck of data-intensive applications has shifted from computation to data
movement. Computational storage pushes computation into the storage device so that
data is processed where it is produced, reducing host memory traffic and end-to-end
latency. Integrating computational storage into an existing distributed file system
is, however, not a matter of interface adaptation alone: physical data layout,
chunking, replica scheduling and result aggregation all change, and several of these
issues silently produce wrong results rather than failing loudly.

This thesis designs and implements a complete compute-offloading mechanism on top of
the SeaweedFS distributed file system and a SmartSSD (an FPGA-equipped SSD):
a range-descriptor based near-storage protocol, cross-chunk orchestration and
aggregation, capability- and load-aware replica scheduling, and a page-cache-aware
adaptive data path. A near-storage Top-K image similarity search operator is built on
top of it.

Two theoretical results are presented. First, we formalise alignment invariance of
offloaded operators and prove that packing-based operators are shift-sensitive with
period 8, so an aligned read window cannot be compensated on the host and the shift
must be pushed down to the device. Second, we prove that per-chunk results are
congruent with the whole-file result if and only if every chunk size is a multiple of
the packing unit, and use it to fix a semantic drift that made the same file return
different values depending on how it was chunked.

Functionality is verified against brute-force references, and measurements show a
26.8% latency reduction for the aligned direct-read path on cold data, a 6.2x speedup
for the adaptive path on cached data (together with the negative result that such a
policy cannot bootstrap itself), and, for image search over 1024-16384 thumbnails,
bit-identical answers with more than 99.999% less transferred data than downloading
the gallery.

**Keywords**: computational storage; near-storage computing; FPGA; distributed file
system; compute offloading; Top-K retrieval

## 第 1 章 绪论

### 1.1 研究背景与意义

过去二十年,处理器与存储设备的性能差距持续扩大,导致大量应用受限于数据搬运
而非计算本身。以"求和、过滤、统计、特征提取"为代表的扫描型负载尤其如此:
它们对每个字节只做极少量的算术运算,却必须把全部数据从存储搬到主机内存、
再从内存搬到处理器缓存。

可计算存储(Computational Storage)提出把一小块可编程计算能力(通常为 FPGA)
直接放进存储设备,让数据"就地处理"。学术界与工业界已有 SmartSSD、CSD 标准
(SNIA)、以及大量基于 FPGA 的加速原型。其核心收益来自三点:消除主机内存带宽
占用、缩短数据通路、以及在主机 CPU 繁忙时仍能提供稳定的服务质量。

然而,现有工作大多聚焦于**单设备、单数据对象**的加速演示。真实系统需要回答
一系列系统性问题:数据如何被分块存放?计算任务如何被定位与下发?多个副本如何
选择?跨设备的部分结果如何聚合?读取窗口必须对齐时,语义是否会改变?
本文正是在 SeaweedFS 这一真实分布式文件系统上,系统地回答这些问题。

### 1.2 国内外研究现状

**可计算存储硬件**:三星 SmartSSD 系列、Xilinx(AMD)的 U.2 加速卡、
以及 SNIA 的 CSD 接口规范,提供了把 FPGA 放进 NVMe 形态因子的硬件基础。
已有工作利用其完成数据库扫描、压缩、加密与正则匹配等任务,普遍报告了显著的
带宽与能耗收益。

**近存计算的软件接口**:一类工作扩展块设备接口(如扩展 NVMe 命令),
另一类工作在文件系统或对象存储层引入"计算下发"接口。SeaweedFS 上游本身
并不提供完整的数据下沉能力,这为本文提供了真实的研究空间。

**分布式存储上的计算下推**:HDFS/Spark 的 Locality-aware 调度、
对象存储的 Select 类接口,都体现了"把计算移到数据附近"的思想,但它们下沉的是
在主存中执行的算子,数据仍需经过主机内存。本文关注的是**数据不进入主机内存**
的极端情形。

**Top-K 相似检索**:Top-K 是典型的"整体算子(holistic operator)",
不能像求和那样简单地分块相加;分布式 Top-K 需要"本地 Top-K + 全局归并"的
两阶段策略。本文将其作为跨块聚合框架的一个非平凡实例加以实现与验证。

## 第 2 章 相关技术基础

### 2.1 可计算存储与 SmartSSD

SmartSSD 是在标准 U.2 固态硬盘形态中集成 FPGA 的设备。主机侧通过 XRT
(Xilinx Runtime)加载 bitstream,并通过 OpenCL/XRT API 向其提交内核任务。
与"把数据读到主机再算"相比,可计算存储的关键收益在于数据通路:

```text
传统:  存储 -> 页缓存 -> 用户缓冲区 -> CPU   (n 字节经过主机内存两次)
近存:  存储 -> 设备内计算单元                (n 字节不经过主机内存)
```

### 2.2 SeaweedFS 的存储模型

SeaweedFS 采用"中心化元数据 + 无状态数据节点"的架构:master 管理数据节点的
拓扑与卷分配,filer 提供文件系统语义,volume server 负责实际数据读写。
文件被切分为若干**数据块(chunk)**,每块作为一个 needle 存放在 volume server
的 `.dat` 文件中。needle 的布局为:

```text
偏移 0      4           12          16      20
   +-------+-----------+-----------+-------+----------+
   | cookie| needle id | data size |   --  | payload  |
   +-------+-----------+-----------+-------+----------+
```

即**数据区起点 = needle 起点 + 20 字节**,且 needle 之间没有填充对齐。
这一点在第 4 章的对齐问题中起决定作用。

### 2.3 直接 I/O 与 P2P 数据通路

`O_DIRECT` 允许进程绕过页缓存直接读写块设备,但要求**文件偏移、传输长度与
缓冲区地址均按块(通常 512 字节)对齐**。P2P(Peer-to-Peer)缓冲区技术进一步
允许把设备内存映射到主机地址空间,使 `pread` 可以把数据直接写入设备侧显存,
从而避免"主机内存中转"。

### 2.4 Top-K 检索基础

给定查询描述子 q 与库中描述子集合 {x_i},Top-K 检索返回距离最小的 K 个元素。
与求和等可加算子不同,Top-K 是整体算子:任意局部结果都不能被单独加减,
但可以证明**全局 Top-K 必然包含于各分块局部 Top-K 的并集**,这一性质构成
本文两阶段聚合的正确性基础。

## 第 3 章 系统总体设计

### 3.1 设计目标与挑战

设计目标:(1) 数据在计算过程中不进入主机内存;(2) 对上层提供统一的多种
寻址方式(文件、对象、数据块);(3) 支持大文件跨块并行;(4) 在设备不可用时
自动降级而不影响可用性;(5) 所有优化都必须可测量、可复现。

主要挑战包括:如何在不读数据的前提下定位计算的物理区间;设备读取对齐后
算子语义是否改变;跨块部分结果如何聚合;多副本如何选择;以及如何在没有
FPGA 的环境下验证正确性。

### 3.2 总体架构

```text
       用户请求(文件 / 对象 / 数据块)
                    |
            +-------v--------+
            |     Filer      |  1 展开 chunk 清单并校验连续性
            |  (元数据+编排) |  2 按副本能力/负载选择执行节点
            |                |  3 并发扇出(上限 8 路)
            |                |  7 聚合各块部分结果
            +-------+--------+
                    |
            +-------v--------+
            |  Volume Server |  4 仅读 needle 元数据,计算物理区间
            |  (数据节点)    |  5 下发区间描述符 + 算子参数
            +-------+--------+
                    |
            +-------v--------+
            |   CSD Agent    |  6 对齐直读 + 设备内计算
            |  (设备侧常驻)  |  8 仅回传小结果
            +-------+--------+
                    v
             SmartSSD (FPGA)
```

### 3.3 计算请求的数据流

以"对文件 F 执行算子 op"为例:

1. Filer 根据 F 的 chunk 清单展开数据块集合,校验其**连续且无空洞**地覆盖
   整个文件,并校验块大小满足聚合正确性前提(见 4.3);
2. Filer 对每个数据块独立选择执行副本并原子预留其负载;
3. 每个数据块对应的请求被下发到持有该块的 volume server;
4. volume server 只读取 needle 元数据,得到该块在 `.dat` 中的物理偏移与长度,
   并换算出一个**对齐读取窗口**;
5. volume server 把 `{data_file, offset, size, read_offset, read_size,
   payload_shift, params}` 发送给本机 CSD agent;
6. agent 以 `O_DIRECT` 读取对齐窗口(绕过页缓存),按 `payload_shift` 跳过
   窗口头部的非数据字节,在设备上执行算子;
7. agent 仅回传计算结果(数值、或 Top-K 列表);
8. Filer 按算子语义聚合各块结果并返回给用户。

### 3.4 区间描述符协议

协议的核心思想是**只传"数据在哪里",不传"数据是什么"**。请求体如下:

```json
{
  "operation": "img_topk",
  "data_file": "/var/lib/seaweedfs/3.dat",
  "offset": 255348, "size": 8388608,
  "read_offset": 254976, "read_size": 8389120, "payload_shift": 372,
  "params": {"k": "5", "rec": "4096", "q": "<base64 描述子>"}
}
```

其中 `read_offset/read_size/payload_shift` 构成**对齐读取窗口**,
`params` 承载算子参数(如 Top-K 的 K、记录长度、查询描述子)。
该设计带来两个性质:(a) 数据内容不经过主机内存;(b) 查询侧只需要发送
描述子(数百字节),**原始查询图像可不出客户端**,具备天然的隐私特性。

### 3.5 设计约束

综合全文的设计与实验,在既有分布式文件系统上引入计算下沉需要满足以下约束:

1. **物理区间与逻辑坐标必须分离**:设备只知道物理区间,文件级语义
   (记录索引、块内偏移)必须由编排层翻译;
2. **算子必须满足对齐不变性,或由设备承担偏移**;
3. **跨块聚合必须满足同余前提**(块大小为打包单元整数倍),且聚合语义
   必须与单块路径一致;
4. **算子参数必须是可下推的小数据**,否则会重新引入数据搬运;
5. **设备不可用时必须有等价降级路径**。

## 第 4 章 关键机制的设计与实现

### 4.1 跨块编排与聚合

Filer 侧实现块清单展平、连续性校验、8 路并发扇出与算子相关的聚合分发。
聚合被抽象为两类:

- **可加数值算子**:各块返回 64 位结果,在模 2^64 环上求和;
- **整体算子(Top-K)**:各块返回局部 Top-K 列表,归并后取全局 Top-K。

### 4.2 对齐不变性与算子分类

**问题**:设备端要求按块对齐读取,而对齐窗口的起点通常早于数据起点 δ 字节。

**定义**:称算子 f 在偏移 δ 下具有**对齐不变性**,若对任意数据段,
`f(window_start = data_start - δ)` 与 `f(window_start = data_start)` 结果相同。

设备侧打包类算子可写为

```text
f(window, n) = Σ_j b[window + j] * 256^(j mod 8)
```

当窗口起点前移 δ 时,数据第 j 字节的位权由 `256^(j mod 8)` 变为
`256^((δ+j) mod 8)`。

**定理 1**:打包类算子具有对齐不变性当且仅当 δ ≡ 0 (mod 8)。

*证明*:若 δ ≡ 0 (mod 8),则对任意 j 有 (δ+j) ≡ j (mod 8),各项位权相同,
故结果相同。反之,若 δ ≢ 0 (mod 8),取长度 1 的数据段且该字节非零,
则结果分别为 `b*256^0 = b` 与 `b*256^(δ mod 8)`,二者不等。证毕。

**推论 1**:对非对齐不变算子,**主机侧无法通过"多读若干字节后裁剪"来补偿**,
因为位移改变了每个字节的位权,而非仅增加若干项。偏移必须作为参数下推到设备。

**推论 2(算子分类)**:`count`、`min/max`、逐字节独立求和属于对齐不变算子;
按字打包求和、以及任何依赖"字节位置模 8"的算子不属于。原型系统中,
SeaweedFS needle 数据区起点为 `needleOffset + 20`,故 δ = 20,`20 mod 8 = 4 ≠ 0`,
恰好落在非不变一侧——这也是原实现"看似零拷贝、实则从未生效"的根本原因。

### 4.3 跨块聚合的语义与正确性

**定理 2**:设文件被划分为若干块,每块按自身起点打包求和,则

```text
Σ_c packed(chunk_c) ≡ packed(whole file)   (mod 2^64)
```

**当且仅当**每块长度均为打包单元(8 字节)的整数倍。

*证明*:**充分性**——若每块长度为 8 的倍数,则块边界与整文件的字边界重合,
每块内部按字打包与整文件按字打包完全一致,逐块求和即为整文件求和。
**必要性**——若某块边界落在字中间,则跨越该边界的两个半字在逐块打包时
分别被视作两个独立字的低位部分,而在整文件打包时它们属于同一个字,
二者对该字的贡献不同,故不相等。证毕。

**由定理 2 得到的两处实现缺陷与修复**:

1. 原实现仅校验块连续覆盖,**未校验块长度是打包单元的整数倍**,该前提因此
   未被保障。修复:在连续性校验中增加该检查。
2. 原聚合使用任意精度整数求和且**不做归约**,而单块路径直接返回设备结果
   (必然小于 2^64)。这导致同一算子的值域依赖于文件被切成几块。
   修复:聚合结果统一按模 2^64 归约,使单块与多块路径语义一致。

**实验佐证**:在 16 块的实验中,聚合返回值为 `54674594798785595809`,
而整文件真值按模 2^64 归约为 `17781106651366492577`,两者之差为
`36893488147419103232 = 2 × 2^64`——即两者同余,差异正是"未归约"所致。

### 4.4 能力感知与负载感知的副本调度

调度目标为字典序优化:`CSD 能力(硬约束) → 在途字节数 → 在途请求数 →
探测延迟 → 主机标识(确定性)`。实现要点:

- **能力探测在临界区之外完成**(结果按 30 秒缓存),临界区仅做内存快照排序
  与原子预留,避免网络探测串行化并发扇出;
- **失败排除集**:重试时把已失败节点排除,保证故障切换真正生效;
- **在途负载以字节计量**,避免大块与小请求被同等对待。

### 4.5 自适应数据通路选择

**动机**:实验显示直读路径在冷数据下更快(省去"磁盘→页缓存→缓冲区"的
第二次拷贝),但在数据已在页缓存时显著更慢。因此需要在**每次请求上自适应决策**。

**机制**:先以 `preadv2(RWF_NOWAIT)` 尝试读取对齐窗口。该调用在数据已驻留
页缓存时立即成功——**且这次调用本身就是数据搬运**,不产生额外开销;
若返回 `EAGAIN` 或短读(部分命中),则丢弃结果并回退到 `O_DIRECT` 整窗重读。
预测失败只会退化为原路径,不会导致请求失败。实测两个原语的探测成本分别为
`mincore` 66µs(4MiB)与 `RWF_NOWAIT` 10µs(未命中),相对 30–200ms 的
请求时延可忽略,故**按请求探测是可行的**。

**负面结论(重要)**:`O_DIRECT` 读取**不填充页缓存**。若计算请求是文件的
唯一访问者,缓存将永远为空,自适应策略会持续命中失败并退化为"永远直读"。
实验证实了这一现象(见 6.4),说明该优化的收益依赖数据同时被普通读路径
(FUSE 挂载、S3 读取、副本同步)访问过;对"仅经计算路径反复访问同一区间"的
负载,需要额外的缓存"自举"机制,并需权衡缓存污染。

### 4.6 分阶段可观测性

设备侧返回 `read_ms`、`kernel_ms` 与读路径标识,经数据节点以
`X-CSD-*` 响应头透传,最终由 Filer 汇总为 `X-Compute-Chunks`、
`X-Compute-Dispatch-Ms`、`X-Compute-Device-Read-Ms`、`X-Compute-Kernel-Ms`、
`X-Compute-Direct-Hits`、`X-Compute-Cache-Hits` 等指标,
使"时间花在哪里"与"数据走了哪条通路"均可观测。

## 第 5 章 近存以图搜图算子的设计与实现

### 5.1 场景与需求

场景:图库(若干图片)存放于 SmartSSD,用户给定一张查询图片,
需要返回最相似的 Top-K 张图片及其相似度。功能需求:(a) 结果与暴力检索一致;
(b) 查询图片本身不出客户端;(c) 图库规模增长时,回传数据量不随之增长。

### 5.2 数据布局与描述子设计

图库作为**一个文件**存放,内容是若干定长记录的拼接,每条记录为
64×64 的 8 位灰度缩略图(4096 字节)。选择整数型描述子是为了让设备可以在
**一次流式扫描**内完成特征提取:

```text
descriptor[0..63]  = 灰度直方图,bin = 像素值 >> 2
descriptor[64..67] = 四个象限的像素值之和
相似度 = 描述子之间的 L1 距离(越小越相似)
```

简化说明:原型使用原始缩略图而非 JPEG 压缩图,以避免在设备侧实现熵解码;
描述子定义是可插拔的,扩展到学习型嵌入向量只需替换该部分。

### 5.3 算子执行流程

设备侧算子 `img_topk` 接收参数 `k`、`rec`(记录长度)、`q`(查询描述子)
与 `base_off`(该块在文件中的逻辑起点),对区间内的**完整记录**逐条计算
描述子与 L1 距离,在片内维护大小为 k 的有序表,最终输出
`索引:距离` 列表(按距离升序)。

### 5.4 跨块两阶段 Top-K 合并

依据"全局 Top-K 包含于各块局部 Top-K 之并",各数据块独立返回局部 Top-K,
由 Filer 归并并截断为 K。该性质使算子可以在不读取全局信息的前提下本地剪枝,
是本设计中"数据并行 + 精确结果"能够同时成立的关键。

### 5.5 逻辑坐标与物理坐标分离(设计缺陷与修复)

**问题**:volume server 只知道该块在 `.dat` 文件中的**物理偏移**,
而记录索引(第几张图片)必须基于该块在**文件中的逻辑偏移**计算。
初版实现直接用物理偏移作为记录索引基准,导致记录边界整体错位
(每条记录被错位最多 4095 字节),索引完全错误,且**距离值也随之为错**。
该缺陷不会引发任何异常,只会安静地返回错误结果。

**发现方式**:通过与暴力检索参考实现逐条比对 Top-K 结果而暴露
(功能验证的价值正在于此)。

**修复**:由 Filer(唯一掌握完整块清单的组件)在每次下发时携带该块的
逻辑起点 `base_off`,设备据此计算记录索引,从架构上消除物理/逻辑坐标混用。

### 5.6 查询隐私与参数下推

由于计算下推只需要描述子,查询图像在客户端完成特征提取后,**图像本身无需上传**;
同时设备只回传 K 个 `(索引, 距离)` 对。因此该设计天然具备"数据最小暴露"特性,
这在隐私敏感的图像检索场景中具有实际价值。

## 第 6 章 实验与结果分析

### 6.1 实验环境与方法

由于开发环境不具备 FPGA,本文实现了一个**软件 CSD agent**:它使用与真实
agent 完全相同的请求契约与计算语义(含对齐窗口与偏移规则),但以主机 CPU
完成算术,从而可在普通机器上部署完整的 master + volume + filer + agent 链路。
所有实验均可由脚本一键复现;数据规模、重复次数与随机种子均被固定。

验证方法采用**独立参考实现交叉验证**:所有算子结果都与另一套独立实现
(Python 参考实现 / 暴力检索)逐位比对,而非仅检查程序是否报错。

### 6.2 正确性验证

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 对齐窗口几何 | 6 种 needle 偏移 × 8 种长度,校验对齐/覆盖/最小性 | 全部满足 |
| 对齐语义等价 | 对齐窗口 + 偏移打包 vs 数据对齐打包(48 组) | 逐位一致 |
| v1/v2 内核兼容 | `shift=0, size=len` 与 v1 语义对比 | 逐位一致 |
| 短读处理 | 分片读取重组、越界返回短计数 | 符合预期 |
| 跨块聚合 | 单块 vs 多块(含 16 块)与整文件真值比对 | 同余(修复后一致) |
| 调度器 | 排除集、字节加权、探测不被串行化、预留/释放 | 全部通过 |
| 图像检索 | 1024/4096/16384 张图库,每种 7 次重复 | 与暴力检索逐位一致 |

单元测试规模:服务端 Go 用例(含新增的聚合语义与调度用例)全部通过;
设备侧主机参考测试 **373 项检查**全部通过。

### 6.3 读路径性能

64MB 文件(16 个 4MB 数据块),每种配置 9 次重复,取中位数(单位 ms):

| 读路径 | 页缓存热 | 页缓存冷 |
| --- | --- | --- |
| 修复前(数据对齐读,无直读) | 32.7 | 257.2 |
| 对齐窗口读(缓冲) | 32.1 | 241.6 |
| 修复后(对齐窗口 + O_DIRECT) | 173.8 | 188.3 |

结论:(1) 冷数据下修复后端到端时延降低 **26.8%**,设备读阶段降低 **31.8%**;
(2) 热数据下直读更慢,原因是绕过页缓存——该现象直接引出 4.5 节的自适应机制;
(3) 对齐导致的额外读取量仅为 **0.0105%**(每条 4MB 记录约 442 字节),
工程代价可忽略;(4) 修复后每次请求 **16/16** 个数据块均命中直读路径。

### 6.4 自适应数据通路

64MB 图库、16 块、9 次重复中位数:

| 策略 | 热(普通读预热) | 冷(每次驱逐) | 缓存命中 |
| --- | --- | --- | --- |
| 始终直读 | 168.5 ms | 197.0 ms | 0/16 |
| 自适应 | 27.1 ms(6.2×) | 204.5 ms(约持平) | 16/16 / 0/16 |

**负面结论**:当页缓存未被普通读路径预热时(仅计算路径访问文件),
自适应策略 7 次请求全部未命中,退化为"始终直读",无任何收益。
其机理是 `O_DIRECT` 不填充页缓存。该结论已在 4.5 节说明,
并作为后续工作(缓存自举机制)提出。

### 6.5 以图搜图实验

图库为 64×64 灰度缩略图拼接,8 个视觉簇,查询取某一簇内图片加噪。
"传统方案"指下载整个图库后在客户端检索。

| 图库规模 | 数据块 | K | 近存时延 | 回传字节 | 传统方案时延 | 传输字节 | 加速比 | 传输减少 | 正确性 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1024 张(4MB) | 1 | 5 | 21.1 ms | 43 | 901.5 ms | 4.19 MB | 42.8× | 99.9990% | 一致 |
| 4096 张(16MB) | 4 | 1 | 48.3 ms | 9 | 3602.2 ms | 16.8 MB | 74.6× | 99.9999% | 一致 |
| 4096 张(16MB) | 4 | 5 | 52.3 ms | 48 | 3583.0 ms | 16.8 MB | 68.5× | 99.9997% | 一致 |
| 4096 张(16MB) | 4 | 20 | 49.5 ms | 196 | 3632.9 ms | 16.8 MB | 73.4× | 99.9988% | 一致 |
| 16384 张(64MB) | 16 | 5 | 154.7 ms | 53 | 14387.7 ms | 67.1 MB | 93.0× | 99.9999% | 一致 |

此外,Top-K 结果与查询所属视觉簇的一致率为 **K/K**(即检索到的图片全部
来自查询图片所属簇),说明描述子设计对合成簇结构具有良好的区分能力
(同簇距离约 2500–2800,跨簇距离约 1.3×10^5)。

**分析**:(1) 回传数据量与图库规模**解耦**(仅随 K 增长),这是近存检索的
本质优势;(2) 近存时延随图库规模近似线性增长(21→52→155 ms),
因为设备仍需扫描全部字节,与"扫描型负载"的预期一致;
(3) 传统方案中"下载"部分随规模线性增长,而"客户端检索"部分在 Python
实现下增长更快(0.9→14.3 s),因此加速比随规模上升。

### 6.6 讨论与有效性威胁

**内部有效性**:软件 agent 与真实 agent 共享协议与算法,但算术在主机完成,
因此设备侧并发度、DMA 与内核流水线带来的差异未被覆盖;
真实 agent 目前是单线程串行处理,在高并发扇出下会成为瓶颈,这是后续工作之一。

**外部有效性**:图库为合成缩略图,描述子为整数直方图 + 象限和,
与真实图像检索中使用的学习型嵌入存在差距;但本文的贡献在于**计算下沉机制与
跨块聚合语义**,描述子是其中可替换的组件。

**结论有效性**:所有功能性结论均以独立参考实现交叉验证,而非仅凭程序输出;
性能结论在共享容器环境下测得,绝对值仅作趋势参考,权威数据需在真实
SmartSSD 上复测(硬件内核重新综合约需 2 小时,命令已归档于仓库文档)。

## 第 7 章 结论与展望

### 7.1 工作总结

本文在 SeaweedFS 与 SmartSSD 上完成了从协议、编排、调度到具体算子的完整
计算下沉设计与实现,并给出了两个可证明的理论结果;共定位并修复 8 个缺陷,
其中 5 个会导致静默错误或间歇性失败。实验表明:冷数据下直读路径可降低
端到端时延 26.8%;自适应通路在缓存命中时加速 6.2 倍(并给出其无法自举的
负面结论);近存以图搜图算子在 1024–16384 张图库上返回与暴力检索逐位一致的
结果,同时将回传数据量降低 99.999% 以上。

### 7.2 主要创新点

1. **对齐不变性与算子分类**(定理 1 及推论):证明按字打包算子的 8 字节周期
   偏移敏感性,说明主机侧裁剪无法补偿,并给出算子分类与接口约束;
2. **跨块聚合同余条件**(定理 2):给出逐块结果与整文件结果同余的充要条件,
   据此修复"同一文件在不同分块下语义漂移"的缺陷;
3. **面向既有分布式文件系统的计算下沉参考设计**:区间描述符协议、
   参数下推通道、五条设计约束,以及对"物理区间/逻辑坐标分离"的架构化处理;
4. **页缓存感知的自适应数据通路**及其负面结论:量化了旁路缓存的收益边界,
   指出近存计算场景下缓存自举的结构性难题。

### 7.3 未来工作

1. 在真实 SmartSSD 上重新综合内核并复测,补齐设备侧并发与流水线的影响分析;
2. **设备侧并发化与流水线**:将 agent 改为并发处理,并引入双缓冲使
   "读取下一块"与"计算当前块"重叠;
3. **缓存自举机制**:探索"首次访问带缓存读取"或基于访问热度的周期性回退;
4. **调度模型化**:建立下沉判决成本模型与整文件全局规划(最小化最大负载),
   替代当前的逐块贪心;
5. **算子扩展**:将描述子替换为学习型嵌入,支持 L2/余弦距离与粗量化,
   并把谓词与范围下推、压缩数据就地计算纳入框架;
6. **可验证卸载**:研究采样复算的检错概率模型,为不可信设备提供结果校验。
