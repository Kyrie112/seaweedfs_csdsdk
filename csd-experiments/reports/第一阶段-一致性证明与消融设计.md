## 0. 结论摘要

本文把已实现的一致性机制形式化为两条定理:

- **安全性**:任何成功返回的结果,都等于某个单一快照上的计算;否则请求显式失败。
  即**不存在静默错误**。
- **活性**:一个已过时的数据版本,在租约释放(或过期)且超过保留期后,
  会在有限次回收中被删除,不会被无限期占用。

并给出**消融设计**:逐一关闭快照令牌、设备自校验、重试、版本保留、租约,
量化每个机制的贡献。

## 1. 系统模型

### 1.1 对象与版本

- 文件 `F` 由块清单 `C = {c_0, …, c_{n-1}}` 描述;
- 每个块 `c_i` 是一个 needle,具有身份 `(needleId, cookie, dataSize)`
  和物理位置 `(dataFile, offset)`;
- 文件条目带有版本 `V = (mtime, C 的摘要)`;
- 数据文件有单调递增的代次 `g`,对应一个保留的 inode(版本链接 `<base>.dat.g<g>`)。

### 1.2 快照

定义**快照** `S = (V, {version(c_i)})`:在某一时刻 filer 读到的文件版本与块清单。
计算请求在开始时绑定一个快照,记为 `S_req`。

### 1.3 租约

读取一个代次 `g` 前获取租约 `l = (id, g, expiry)`,读取结束后释放;
若持有者崩溃,租约在 TTL 后自动过期(不再钉住 `g`)。

### 1.4 故障模型

允许:filer/volume/agent 崩溃并重启、网络超时、请求重试、后台整理(compaction)、
覆盖写、删除、needle 物理区间被复用。
**不假设**:时钟完全同步;不假设存储介质不会丢失数据。

### 1.5 静默错误

若请求返回成功,但其结果 `R` 不满足
`R = Compute(S)`(对任何单一快照 `S`),则称发生一次**静默错误**。
本文的目标是证明静默错误不可能发生。

## 2. 定理 1:安全性(无静默错误)

### 2.1 陈述

对任意请求,其返回满足:

```text
要么 返回错误(显式失败),
要么 存在某个快照 S,使 结果 = Compute(S)。
```

### 2.2 证明

**单块请求**

1. Filer 在展开清单后生成 `S_req` 与令牌 `tok = digest(C)`;volume 收到的
   `csize` 来自同一份清单,因此期望的块长度属于 `S_req`;
2. volume 在本地 needle map 中定位块,若长度与 `csize` 不符,直接返回
   `stale_range`(显式失败);若相符,说明它定位到的 needle 与 `S_req` 的块一致
   (身份由 `needleId/cookie` 与长度共同确定);
3. 设备读取前解析 needle 头,校验 `cookie/needleId/dataSize`;不匹配则拒绝;
   读取后再校验一次,若读取期间头部变化(区间被移动/复用),拒绝并返回
   `stale_range`;
4. 因此,只有当设备读到的字节确实属于 `S_req` 中的块时,才会得到结果 `R`;
   于是 `R = Compute(S_req)`。

**多块请求**

1. 每个块按上述过程,要么失败,要么满足 `R_i = Compute_i(S_req)`;
2. Filer 在聚合前校验:各块回传的令牌摘要一致、块序号齐全;
   否则按一致性等级处理(L1 标注、L2 拒绝);
3. 聚合函数是确定性的(模 2^64 求和 / Top-K 归并),因此
   `R = Aggregate({R_i}) = Compute(S_req)`。

**冲突与重试**

若某块返回 `stale_range`,请求级重试会**重新读取 filer 条目**,
得到新的快照 `S'` 并重新绑定。因此重试后的结果要么属于 `S'`,
要么显式失败;不会出现"半旧半新"的聚合结果(每次尝试只使用一个令牌)。

**结论**:所有成功路径都对应某个单一快照;其余路径显式失败。证毕。

### 2.3 证明依赖的假设

| 假设 | 说明 | 不成立时的后果 |
| --- | --- | --- |
| needle 头校验可靠 | cookie 为随机值,复用区间时几乎不可能碰撞 | 极小概率的误判 |
| 令牌覆盖块清单 | 清单变化 → 摘要变化 | 已被摘要设计覆盖 |
| 聚合确定性 | 同一输入必得同一输出 | 已由测试保证 |
| 租约保护版本 | 读取期间版本不被回收 | 若被强制回收,则退化为 `stale_range`(仍是显式失败) |

### 2.4 边界(不声称的内容)

- **不是线性一致/可串行化**:没有跨文件事务;
- **不是全局快照**:版本保护是单卷本地的;
- **版本粒度是卷数据文件代次**,不是记录级 MVCC;
- 对于"时钟不同步"的极端情形,只保证"要么正确、要么失败",不保证实时性。

## 3. 定理 2:活性(旧版本终将被回收)

### 3.1 陈述

设代次 `g` 已不是当前代次,且没有任何未过期租约钉住它。
则从某一时刻起,经过至多一个保留期加一次回收周期,`g` 对应的版本文件会被删除。

### 3.2 证明

1. 回收条件为:`g ≠ current` ∧ `activeLeases(g) = 0` ∧ `age(g) ≥ retention`
   ∧ `g` 不在"最近 N 个历史版本"内;
2. 由假设,`g` 已过时(非当前)、无活跃租约;
3. 租约只有三种归宿:显式释放、TTL 过期、持有者崩溃后 TTL 过期;
   三者都在有限时间内使 `activeLeases(g)` 变为 0;
4. 时间单调推进,`age(g) ≥ retention` 终会成立;
5. 历史版本数有限(每次整理最多新增一个),当 `g` 不属于最近 N 个时条件满足;
6. 下一次回收扫描会删除它。证毕。

### 3.3 推论(空间有界)

- 每卷同时保留的历史版本 ≤ `max(活跃租约钉住的版本数, N)`;
- 因此空间占用有上界:当前数据 + 被钉住的旧版本 + N 个最近历史版本;
- 若出现"无限长读",其租约可持续续期,从而阻止回收——
  这是**有意的安全优先**:宁可占空间,不可打断正确性;
  运维可通过强制回收(并用 M1 兜底)打破僵局。

## 5. 消融设计(P1-6)

### 5.1 消融维度

| 编号 | 关闭的机制 | 预期影响 |
| --- | --- | --- |
| A0 | 全部开启(基线) | — |
| A1 | 关闭快照令牌校验 | 无法发现"块清单变化";F1 类场景可能出现混版 |
| A2 | 关闭设备侧 needle 头自校验 | 读取期间区间被复用 → 静默错误(M1 前的行为) |
| A3 | 关闭 `stale_range` 重试 | 可恢复的冲突变成失败(时延/成功率下降) |
| A4 | 关闭版本保留(退回直接替换 `.dat`) | 整理与计算并发时出现静默错误 |
| A5 | 关闭租约(仅按时间回收) | 长读期间版本可能被回收 → 退化到失败 |
| A6 | 关闭跨块聚合校验 | 多块混版无法发现 |

### 5.2 指标

- **正确性**:按 M4 判据(结果属于某快照 / 显式失败);
- **成功率**:在注入场景下成功返回的比例;
- **时延**:正常路径与冲突路径的 P50/P99;
- **空间**:保留版本数、额外占用;
- **可观测**:`X-Compute-Stale-Chunks`、`X-Compute-Retry-Reason`。

### 5.3 执行方式

每个维度通过运行期开关或构建标签关闭(优先运行期,便于同一集群对比),
在同一负载与同一注入场景下重复 ≥5 次,记录到 `results/ablation.csv`。

### 5.4 预期结论

- A2/A4 关闭后应出现**静默错误**(证明机制必要);
- A3 关闭后成功率下降、失败率上升(证明自愈价值);
- A5 关闭后长读场景出现失败(证明租约必要);
- A1/A6 关闭后混版风险上升(证明令牌/聚合校验必要);
- 正常路径时延在各档之间应无显著差异(**机制不拖慢快路径**)。
