## 1. P0:理论 + 实验闭环,最推荐(约 7–9 周)

### P0-1 下沉判决成本模型与 break-even 分析

- **研究问题**:在什么条件下,近存计算一定优于"搬回主机再算"?
- **具体工作**:
  1. 建立 `T_host` 与 `T_offload` 的解析模型(数据量、链路带宽、设备读带宽、算子计算强度、主机 CPU 负载);
  2. 推导 break-even 不等式,给出"该下沉 / 不该下沉"的判据;
  3. 在三个维度上扫描验证(数据量 × 带宽限制 × 算子强度);
  4. 用现有数据集拟合参数,给出误差分析。
- **产出**:成本模型公式、break-even 相图、预测 vs 实测误差表。
- **工作量**:约 8–10 人日(建模 3 + 实验 4 + 写作 2)。
- **现有基础**:已有冷/热路径数据、带宽受限实验脚本,可直接复用。
- **论文位置**:第 4 章(机制)或独立"模型"一节;第 6 章验证。

### P0-2 全局调度规划与近似算法

- **研究问题**:多块、带宽受限、多副本条件下,如何最小化整体完成时间?
- **具体工作**:
  1. 形式化为"最小化 makespan / 最大链路负载"的约束优化问题;
  2. 给出 LP 松弛下界 + 贪心近似算法,分析近似比;
  3. 与现状(逐块贪心)、轮询、随机对比;
  4. 在 3 节点与模拟大规模拓扑上评估。
- **产出**:问题形式化、算法伪码、近似比证明/分析、四组对比实验。
- **工作量**:约 10–12 人日。
- **现有基础**:`filer_csd_scheduler*` 已实现逐块贪心与副本亲和,可直接作为 baseline。
- **论文位置**:第 4/5 章;这是"从工程到研究"的关键增量。

### P0-3 一致性保证的安全性 / 活性证明

- **研究问题**:现有快照 + 租约机制,能否形式化证明"绝不静默返回错误结果"?何时一定能回收?
- **具体工作**:
  1. 定义系统模型(对象、版本、快照、租约、故障模型);
  2. **安全性**:证明"任何返回的结果都属于某个单一快照"(或显式失败);
  3. **活性**:证明"租约释放/过期后,旧版本终将被回收"(无饥饿);
  4. 用 TLA+/状态机或不变式推导给出可检查的论证。
- **产出**:形式化定义、两条定理与证明、状态机图。
- **工作量**:约 5–7 人日。
- **现有基础**:M1–M4 的机制与故障矩阵已就位,只差形式化。
- **论文位置**:第 4 章(正确性);这是"有证明"的加分项。

### P0-4 压缩 needle 的就地计算

- **研究问题**:真实图像/日志数据常被存储层压缩,当前会绕过近存路径;能否在设备侧解压后计算?
- **具体工作**:
  1. 在 agent 侧实现流式解压(或与内核共享解压缓冲);
  2. 保持对齐/偏移语义与短读校验;
  3. 与未压缩路径对比:时延、带宽、CPU 占用;
  4. 统计真实数据集的压缩率与绕行比例(已有 MNIST 案例)。
- **产出**:压缩路径实现、对比实验、适用性分析。
- **工作量**:约 8–10 人日。
- **现有基础**:M1 已在真实数据上发现"压缩即绕行",动机充分。
- **论文位置**:第 5 章(机制扩展);这是真实可用性的关键。

### P0-5 tan 集群 + 真机复测 + 故障矩阵补齐

- **研究问题**:本地三节点结论能否在真实三机 / SmartSSD 上复现?
- **具体工作**:
  1. 在 tan09/10/11 部署(`deploy_csd_cluster.sh` 已就绪);
  2. 补齐 F2/F3/F5/F6(删除、整理、副本滞后、灰度升级);
  3. 在 .9 重综合 v2 内核并测 P2P 端到端;
  4. 记录权威时延/吞吐。
- **产出**:真实集群实验表、故障矩阵完整版、真机性能数字。
- **工作量**:约 6–8 人日(含 2 小时内核综合与等待)。
- **现有基础**:脚本、判据、日志模板已全部准备好。
- **论文位置**:第 6 章;这是"权威数字"的来源。

## 2. P1:显著增量(每项 1–2 周)

### P1-1 范围与谓词下推

- **研究问题**:只计算文件的一段区间/满足谓词的数据,能省多少带宽?
- **工作**:把 `ResolveChunkManifest` 已支持但被写死的 `startOffset/stopOffset` 暴露到 API;实现按块裁剪与部分块扫描;做"选择性 1%/10%/50%"实验。
- **产出**:选择性扫描的带宽-时延曲线。
- **工作量**:5–7 人日。
- **论文位置**:第 5 章(接口扩展)+ 第 6 章。

### P1-2 可结合算子代数

- **研究问题**:哪些算子可以安全地跨块部分归约?不可结合的如何两阶段处理?
- **工作**:统一 partial-reduce 框架(sum/min/max/count/histogram/方差/点积/汉明距离);对中位数/分位数实现"本地草图 + 全局合并";给出代数条件。
- **产出**:算子分类表、框架伪码、精度/开销实验。
- **工作量**:7–10 人日。
- **论文位置**:第 5 章;与已有 Top-K 合并形成体系。

### P1-3 描述子升级与真实数据集扩展

- **研究问题**:整数描述子的检索质量边界在哪?学习型嵌入带来多少提升?
- **工作**:在 MNIST 基础上增加自然图像数据集(如 CIFAR-10 子集),对比直方图/网格/HOG/嵌入(可用预计算特征);给出质量-成本权衡。
- **产出**:多描述子对比表、precision@K 曲线。
- **工作量**:7–10 人日(数据准备占一半)。
- **论文位置**:第 5/6 章;补齐"外部有效性"。

### P1-4 尾延迟、公平性与能耗

- **研究问题**:近存路径在 P99/P999、并发公平性和能耗上是否更优?
- **工作**:压力测试、Jain 公平性指数、功耗计/板卡功耗读数、每 GB 能耗。
- **产出**:尾延迟曲线、公平性表、J/GB 对比。
- **工作量**:5–8 人日。
- **论文位置**:第 6 章;SmartSSD 差异化最强的指标。

### P1-5 设备侧并发化与双缓冲流水线

- **研究问题**:当前 agent 串行处理 + 读算串行,吞吐损失多少?
- **工作**:agent 改并发处理;引入双缓冲(读第 i+1 块时算第 i 块);测吞吐/时延。
- **产出**:流水线前后对比、设备利用率曲线。
- **工作量**:5–7 人日。
- **论文位置**:第 5 章(实现)+ 第 6 章(实验)。

### P1-6 系统消融矩阵

- **工作**:逐一关闭 P2P / O_DIRECT / 调度器 / 跨块 / 版本保留 / 租约,量化各自贡献。
- **产出**:消融表(论文最实用的表之一)。
- **工作量**:3–5 人日(脚本已有基础)。

## 7. 不建议做(低论文价值)

| 事项 | 原因 |
| --- | --- |
| 单纯把 agent 改成多线程但不做对比实验 | 工程劳动,无研究结论 |
| 反复调参刷指标 | 不可证伪,审稿易质疑 |
| 引入外部协调服务(etcd)做版本源 | 偏离"存储系统内生一致性"的主题 |
| 重写调度器只为代码好看 | 无增量结论 |
| 无真实数据的纯合成实验 | 外部有效性弱(已有 MNIST,继续补真实数据即可) |
