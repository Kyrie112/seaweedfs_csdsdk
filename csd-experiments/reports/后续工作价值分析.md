# 毕业设计后续工作价值分析

> 配套文档:[后续工作选题清单.md](后续工作选题清单.md)(选题清单)
> 本文回答的是:**这些选题里,哪些真的值得做、为什么、风险在哪、应该按什么顺序做。**

## 0. 判断标准

一个选题值不值得做,只看三条:

1. **能写进论文**:有明确的问题定义,能落到某一章;
2. **有可证伪的结论**:能提出假设,并用实验或证明支持/推翻;
3. **有可信证据**:能产出数据、图表、定理或可复现实验。

按这个标准,**"多写代码"本身不加分**。当前系统在功能上已经相当完整,
继续堆功能是边际收益递减;真正缺的是**证明、模型、权威数字和消融**。

## 2. P0 逐项分析

### P0-3 一致性安全性 / 活性证明 —— 最值得做

**为什么值**

机制(快照令牌、设备自校验、版本保留、租约回收)已经全部实现并有故障矩阵;
现在缺的只是把它们**形式化**。这是"只写不写码"就能拿到的理论增量。

**要证明什么**

- **安全性**:任何成功返回的结果,都必须属于某个单一快照;否则必须显式失败。
  (直白地说:不存在"静默返回错误结果"的执行。)
- **活性**:租约释放或过期后,旧版本终将被回收(不会无限期占用空间)。

**风险与边界**

- 低风险。唯一要避免的是**过度声称**:它不满足严格可串行化,
  也不是跨节点全局快照;论文中必须写清"快照一致 + 显式失败"的边界。
- 需要定义清楚失败模型(节点崩溃、租约过期、Filer 重启)。

**产出**

系统模型、两条定理与证明、状态机图、与故障矩阵的对应关系。

---

### P0-1 下沉判决成本模型 —— 理论增量最便宜

**为什么值**

把"什么情况下该下沉"从经验判断变成公式。现有冷/热路径数据、带宽受限实验
可以直接用来拟合和验证。

**要做什么**

1. 建立 `T_host`(搬运 + 主机计算)与 `T_offload`(调度 + 设备读 + 内核 + 回传)的解析模型;
2. 推导 break-even 不等式,确定主导变量(数据量、带宽、算子强度、CPU 负载);
3. 三维扫描实验(数据量 × 带宽 × 算子强度),验证预测边界;
4. 给出"预测 vs 实测"的误差表。

**风险**

模型容易做得过粗或过拟合。缓解:明确假设、做敏感性分析、如实报告误差,
不要假装它是精确模型。

**产出**

break-even 不等式、相图、"该下沉 / 不该下沉"的判据。答辩时"为什么下沉"
这类问题会直接被这张图回答。

---

### P0-5 tan 集群 + 真机复测 —— 唯一能提供权威数字的途径

**为什么值**

没有真机数据,所有性能结论都只能写成"本地趋势"。这是论文可信度的分水岭。

**要做什么**

1. 在 tan09/10/11 部署(`deploy_csd_cluster.sh` 已就绪);
2. 补齐故障矩阵中依赖真实多机的 F2/F3/F5/F6;
3. 在 .9 重综合 v2 内核,测 P2P 端到端;
4. 记录权威时延/吞吐/CPU 占用。

**风险**

环境依赖(当前容器不可达 tan09–11)、内核综合约 2 小时、硬件差异。
**拿不到就如实写"受限",绝对不要编数字。**

**产出**

真实集群实验表、完整故障矩阵、真机性能数字。

---

### P0-4 压缩 needle 就地计算 —— 推荐,但要限定范围

**为什么值**

真实数据(MNIST)已经证明"压缩即绕行"——存储层自动 gzip 后,
CSD 路径被完全绕过。这是**可用性级**的问题,动机非常硬。

**两种做法与取舍**

| 做法 | 优点 | 代价 |
| --- | --- | --- |
| 设备内(FPGA)解压 | 真正的零拷贝 | 实现成本高、需重综合 |
| agent 侧流式解压 | 实现快、可复用现有内存 | 数据经过主机 CPU,**不再是严格零拷贝** |

**建议**:先做 **agent 侧流式解压 + 内存复用**,在论文里明确这是折中;
重点测"绕行率从 100% 降到多少"与"额外 CPU 开销"。

---

### P0-2 全局调度规划 —— 推荐,但缩小野心

**为什么值**

从"逐块贪心"升级到"整请求规划",是明显的算法贡献。

**风险**

在"多副本 + 带宽约束 + 异构设备"下做**近似比证明**非常难,容易做成半吊子。
建议只做**受限模型**:

- 同构副本、带宽上限已知;
- 给出 LP 下界;
- 用 LPT / 贪心近似与下界对比;
- 明确近似结论只在受限条件下成立。

**结论**:有时间做完整版;没时间就做"整请求贪心 + LP 下界对比",
不强行写近似比。

## 3. P1 简评

| 选题 | 判断 |
| --- | --- |
| **P1-6 消融矩阵** | 半天到两天,评审最爱看,直接回答"每个机制贡献多少"。**优先于任何新功能**。 |
| **P1-1 范围/谓词下推** | 代码量小(`ResolveChunkManifest` 已支持),带宽收益直观,能画"选择性 1%/10%/50%"曲线。 |
| **P1-4 尾延迟** | 改一下压测脚本就能出 P99/P999,半天。**做**。 |
| P1-4 能耗 | SmartSSD 差异化最强,但**没有功率计就别做**;能测就一定测。 |
| P1-2 算子代数 | **只做 3 个**:min/max、histogram、一个不可结合算子(中位数草图)。不要做十个。 |
| P1-3 描述子升级 | 做"描述子族对比"(直方图 / 网格 / 梯度方向)即可;**别去训学习型嵌入**。 |
| P1-5 设备侧并发/流水线 | 本质是工程优化;除非需要"吞吐"故事,否则优先级低于 P0 与 P1-1/P1-6。 |

## 5. 最终顺序(按性价比)

```text
第 1 周  P0-3 一致性证明 + P1-6 消融矩阵
第 2 周  P0-1 成本模型
第 3 周  P1-1 范围下推
第 4 周  P0-5 tan 集群 + 真机复测
第 5 周  P1-4 尾延迟(+能耗,若有功率计)
第 6 周  P1-2 受限版算子代数(3 个算子)
        └─ 若还有时间:P0-2 受限版全局调度
```

前 4 周决定论文下限:**证明 + 模型 + 真实数字 + 消融**;
后 2 周是加分项。

---

## 6. 不建议做的事

| 事项 | 原因 |
| --- | --- |
| 单纯把 agent 改成多线程但不做对比实验 | 工程劳动,无研究结论 |
| 反复调参刷指标 | 不可证伪,评审易质疑 |
| 引入 etcd 等外部协调服务做版本源 | 偏离"存储系统内生一致性"的主题 |
| 重写调度器只为代码好看 | 无增量结论 |
| 无真实数据的纯合成实验 | 外部有效性弱(已有 MNIST,继续补真实数据) |
| 追求学习型描述的 SOTA | 那是 CV 论文的工作,不是系统论文的贡献 |

---

## 7. 一句话总结

**当前系统不缺功能,缺的是"证明、模型、权威数据和消融"。**
最值得投入的是 **P0-3 → P0-1 → P0-5 → P1-6 → P1-1**;
EC、PQ 这类"听起来高级"的题目,边际收益远低于它们的风险。
