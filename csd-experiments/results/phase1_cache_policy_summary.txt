Adaptive data path selection (cache policy) experiment
SeaweedFS master+volume+filer, file 64MB -> 16 chunks, 9 reps/config
warm = payload seeded into the page cache by a normal (non-compute) read before each request
cold = payload evicted with fadvise(DONTNEED) before each request

direct_hits per request: {'direct': [16], 'auto': [16]}
consistency: distinct results = {'190022035469879755652'}

note: with only the compute path reading the file, the page cache is never
populated (O_DIRECT does not fill it), so 'auto' degenerates to 'direct'.
The warm numbers above are obtained by seeding the cache with a normal read,
which is what FUSE/S3/replication traffic does in a real deployment.
