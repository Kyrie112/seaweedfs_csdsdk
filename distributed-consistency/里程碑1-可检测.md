# M1 可检测:快照令牌 + 设备自校验 + 指标

> 目标:把最危险的两类**静默错误**(C2 后台整理移动数据、C3 区间被复用)变成**显式失败**。
> 本里程碑不改变默认结果语义,只增加"发现问题"的能力。
> 方案依据:[PLAN 第 5.1、5.2、5.6 节](../分布式一致性问题分析与开发计划.md)。

## 1. 范围与验收

**做什么**

- 定义并传递快照令牌(Filer → Volume → Agent → Filer);
- 设备侧在读取前后各校验一次 20 字节 needle 头;
- 暴露一致性相关指标;
- 补齐单元测试与实验台对照实现。

**不做什么**:不引入重试策略(M2)、不引入卷代次/租约(M3)、不实现故障注入矩阵(M4)。

**出口条件**

| 判据 | 标准 |
| --- | --- |
| 静默错误 | 注入"读取期间替换 needle / 区间复用"时**不再返回数值结果** |
| 正常路径 | 结果与改造前**逐位一致** |
| 性能 | 端到端时延回归 < 5%;设备读取阶段增量 < 1% |
| 回归 | 服务端全部用例 + 设备侧 491 项检查通过 |
| 可观测 | 4 个一致性指标可在响应头读到 |

## 2. 步骤

### T1.1 定义快照令牌与保留键名

- **目标**:把"这次计算针对哪个版本"变成可传递的数据结构;
- **前置**:Q1(filer store 是否提供单调 revision)、Q3(保留键名约定);
- **改动**:新建 `weed/server/filer_compute_consistency.go`;
- **关键流程**:
  1. 定义 `SnapshotToken{fileId, entryVersion, chunkDigest, deadline}` 与
     `ChunkToken{snapshot, chunkIndex, fileId, expectedSize, volumeGen}`;
  2. 约定下推键名(建议 `snap` / `chunk` / `vgen`),并加版本前缀防止与算子参数冲突;
  3. 实现 `DigestChunks(chunks) string`:对规范化后的块清单(序号、offset、size、fileId)求哈希;
  4. 为令牌实现 `String()` 与日志友好摘要(前 8 位十六进制即可);
- **验证与通过标准**:单元测试覆盖"同样清单 → 相同摘要""顺序不同但集合相同 → 摘要不同(或按约定归一)";
- **产出**:结构体、常量、摘要函数、单元测试;
- **回滚**:新增文件,删除即可;
- **风险**:若 filer store 无 revision,`entryVersion` 退化为 `(mtime, mtimeNs)`,
  需在注释与文档中明确其精度限制。

### T1.2 Filer 生成令牌

- **目标**:一次请求只生成一份令牌,保证所有块共享同一版本视角;
- **前置**:T1.1;
- **改动**:`weed/server/filer_server_handlers_proxy.go`
  (`proxyComputeToVolumeServer` / `proxyMultiChunkCompute`);
- **关键流程**:
  1. 在 `resolveComputeChunks` 成功、`validateChunksCoverFile` 通过之后生成令牌;
  2. 为每个块构造 `ChunkToken`(填入序号与期望长度);
  3. 通过现有 `params` 通道下推(`fetchFromComputeReplica` 已在用该机制下发 `base_off`);
  4. 令牌摘要打到 V(1) 日志,便于与实验数据对齐;
- **验证与通过标准**:单次多块请求日志中只出现一个令牌摘要,且各块的 `chunk` 序号连续;
- **产出**:令牌生成与下推代码;
- **回滚**:revert 该提交;不影响其它路径;
- **风险**:单块快路径也要生成令牌,否则两条路径语义不一致。

### T1.3 Filer 聚合前校验

- **目标**:聚合前确认"所有块来自同一令牌、序号齐全";
- **前置**:T1.2;
- **改动**:`filer_server_handlers_proxy.go`(聚合前)与 `filer_compute_aggregation.go`;
- **关键流程**:
  1. 收集各块回传的令牌摘要与块序号;
  2. 校验:序号集合 == `{0..n-1}` 且令牌摘要唯一;
  3. 不满足时按一致性等级处理:L1 记为"未标注快照"并打标,L2 直接失败(M2 才引入重试);
  4. 结果写入响应头 `X-Compute-Snapshot` 与 `X-Compute-Consistency-Level`;
- **验证与通过标准**:构造"某块令牌不同"的假响应,断言请求被标记或失败,**不会静默聚合**;
- **产出**:校验逻辑与单元测试;
- **回滚**:revert;
- **风险**:若设备未实现回传,需区分"老 agent 未回传"与"令牌不一致",
  前者按兼容策略降级为 L0 并打标,不能误判为错误。

### T1.4 Volume 下发前校验

- **目标**:在下发前发现"本地 needle 已不是期望的那一个";
- **前置**:T1.1;
- **改动**:`weed/server/csd_compute.go`(`tryHandleCSDCompute`、`csdOperatorParams`);
- **关键流程**:
  1. 从 `params` 取出 `snap` / `chunk`;
  2. 在 `NeedleComputeRegion` 得到区间后,额外比对:目标 needle 的 cookie/id 与
     描述符一致、数据长度与 `expectedSize` 一致;
  3. 不匹配 → 返回结构化错误 `stale_range`(而不是像现在这样回落到脚本路径);
  4. 记录 `X-CSD-Stale-Range` 计数;
- **验证与通过标准**:单元测试构造"长度不匹配/cookie 不匹配"两种输入,断言返回 `stale_range`;
- **产出**:校验逻辑、错误类型、单测;
- **回滚**:revert;注意保留原有的 cookie 比对(它是既有保护,不要删);
- **风险**:`stale_range` 若直接冒泡成 500,会让正常业务变得更脆——
  这正是 M2 要补重试的原因,因此本步需明确"L1 下允许回落脚本路径并打标"。

### T1.5 设备侧区间自校验

- **目标**:让"哑读"的设备能发现"这段字节不再属于我要算的对象";
- **前置**:T1.1;Q2(是否需要额外 fd);
- **改动**:`smartssd/src/csd_agent.cpp`、`smartssd/src/aligned_range.h`;
- **关键流程**:
  1. 在 `aligned_range.h` 中新增 `NeedleHeader` 解析与比对工具
     (cookie、needle id、数据长度按 SeaweedFS needle 布局解析);
  2. 读取前:解析 `[offset-20, offset)` 的头部,与描述符比对;不匹配 → 返回 `stale_range`;
  3. 读取后:再次读取同一头部,与读取前的快照比对;
     不一致 → 丢弃数据并返回 `stale_range`(说明读取期间被移动/复用);
  4. 计数 `stale_ranges` 并在审计日志中输出;
  5. 保持"默认路径行为不变":无令牌时按老行为工作(兼容老 volume);
- **验证与通过标准**:
  - `make -C smartssd test` 新增用例覆盖:头部不匹配、读取前后头部变化、正常路径;
  - 保持 491 项既有检查通过;
- **产出**:头部解析与校验、计数、参考测试;
- **回滚**:revert;设备侧改动与协议解耦,老 volme 不受影响;
- **风险**:多两次小读取;若落入冷缓存可能增加时延,需在 5.4 性能小节实测。

### T1.6 软件 agent 同步实现

- **目标**:让实验台能复现一致性问题(否则 M4 无法验证);
- **前置**:T1.5;
- **改动**:`csd-experiments/tools/csd-agent-sim/main.go`;
- **关键流程**:
  1. 实现与 C++ 侧**等价**的头部校验逻辑(同样的字段、同样的失败语义);
  2. 增加可控开关 `-fault-inject=<mode>`(如"读取前篡改头部""读取中途替换"),供 M4 使用;
  3. `/v1/stats` 暴露 `stale_ranges` 计数;
- **验证与通过标准**:手工注入一次篡改,确认返回 `stale_range` 且计数 +1;
- **产出**:软件 agent 对照实现;
- **回滚**:revert;
- **风险**:必须与 C++ 实现保持字段级一致,否则"实验台验证通过"不能代表真机。

### T1.7 一致性指标导出

- **目标**:让一致性问题可被观测(否则"没观察到"不等于"没发生");
- **前置**:T1.3、T1.4;
- **改动**:`filer_server_handlers_proxy.go`、`csd_compute.go`;
- **关键流程**:按 PLAN 5.6 输出
  `X-CSD-Stale-Range`、`X-Compute-Stale-Chunks`、`X-Compute-Consistency-Level`、`X-Compute-Snapshot`;
- **验证与通过标准**:正常情况下指标存在且为 0 / L1;注入故障时计数增长;
- **产出**:指标透传;
- **回滚**:revert;
- **风险**:指标名一旦对外公布就是接口,需与 PLAN 5.6 保持一致,改动要同步更新文档。

### T1.8 单元测试与回归

- **目标**:把上述能力固化为可回归的测试;
- **前置**:T1.1–T1.7;
- **改动**:`weed/server/*_test.go`、`smartssd/src/range_sum_test.cpp`;
- **关键流程**:
  1. 服务端:令牌生成/摘要稳定性、聚合前校验(序号缺失、令牌不一致)、
     Volume 校验(cookie/长度不匹配)、兼容性(老 agent 不回传令牌);
  2. 设备侧:头部解析正反用例、读取前后变化、无令牌时的兼容路径;
  3. 全量回归:服务端用例 + 设备侧 491+ 项 + 构建;
- **验证与通过标准**:全部通过;新增用例数量与覆盖点写入步骤记录;
- **产出**:测试代码与结果;
- **回滚**:revert;
- **风险**:测试若依赖真实并发时序会不稳定,应使用可控注入而非 sleep。

## 4. 决策门 D1

M1 结束时必须回答:**设备侧自校验的代价是否可以接受?**

- 若时延增量 < 5% → 进入 M2;
- 若超出 → 先优化读取路径(如合并两次头部读取为一次),再评估是否继续。
