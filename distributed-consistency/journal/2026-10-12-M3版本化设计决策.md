# 设计决策 2026-10-12:M3 升级为"版本化快照与延迟回收"

> 关联:[PLAN 5.4](../../分布式一致性问题分析与开发计划.md)、[里程碑3-版本化快照与延迟回收.md](../里程碑3-版本化快照与延迟回收.md)、
> [进度看板.md](../进度看板.md)

## 1. 决策

放弃"仅靠检测 + 失败"的方案作为主路径,改为**版本保留 + 引用计数 + 延迟回收**
(MVCC 式):

- **老任务读老版本**:请求开始时确定版本,之后按"该代次的数据文件"读取,不再受后续改写影响;
- **新写入追加为新版本**:SeaweedFS 的覆盖写本来就是追加语义,无需改动;
- **老版本延迟回收**:没有请求引用它、且超过宽限期之后才删除。

M1 的检测能力保留,但角色从"主路径"变为**兜底**(仅强制回收/引用丢失时触发)。

## 2. 决策理由

| 理由 | 说明 |
| --- | --- |
| 语义更强 | 从"不出错"升级为"老任务始终成功且结果自洽",真正达成 L2(全请求快照) |
| 聚合需要 | 跨块算子必须让所有块属于同一版本;靠"检测到就失败"无法在数据频繁变更时稳定工作 |
| 与现有架构契合 | 写入已是追加;描述符已携带 file/offset/size,cookie 校验 M1 已就位 |
| 现有机制挡路点单一 | 只有整理(compaction)的提交阶段把旧文件删掉,改动集中 |

## 3. 已核实的关键事实

| 事实 | 位置 | 影响 |
| --- | --- | --- |
| 整理的提交阶段是"删除 + 替换" | `weed/storage/volume_vacuum.go` 约 269–283 行(`os.RemoveAll(.dat)` + `os.Rename(.cpd→.dat)`) | 这是必须改的地方 |
| 提交在 `dataFileAccessLock` 写锁内、带 `.cpc` 崩溃标记 | 同上 | 版本改名要接进既有恢复流程 |
| 卷扫描只认 `.idx` / `.vif` | `weed/storage/disk_location.go` 的 `isValidVolume()` | 版本文件后缀避开这两种即可不被误加载 |
| 启动时会处理 `.cpc/.cpd/.cpx` 残留,忽略其它文件 | `disk_location.go:reconcileCompactStates()` | 版本文件不会被它清理,但提交路径必须与它协作 |
| 描述符已包含文件路径 | `weed/storage/volume_read.go` `NeedleComputeRegion.DataFile` | 指向代次文件即可,**协议无需新增字段** |

## 4. 与既有里程碑的关系

```text
M1 可检测(已完成)      → 退化为兜底:强制回收/引用丢失时显式失败
M2 可规避(未开始)      → 保留:错误分类与 stale_range 重试
M3 版本化快照(本文档)  → 升级为核心机制:版本保留 + 引用回收
M4 可验证(未开始)      → F3 的期望改为"在途请求成功读到旧版本"
```

## 5. 主要风险(已登记到 M3 文档与 PROGRESS)

| 编号 | 风险 | 缓解 |
| --- | --- | --- |
| V1 | Filer 重启丢失内存引用表 → 误回收 | TTL + 宽限期 + 保守回收条件,必要时持久化 |
| V2 | 长尾请求长期占用旧版本 | 租约上限 + 强制回收 + M1 兜底 |
| V3 | 空间放大 | 版本数/空间上限 + 磁盘压力兜底 + 参数可调 |
| V4 | 崩溃恢复路径复杂化 | 复用 `.cpc` 标记流程 |
| V5 | 版本文件污染卷管理 | 后缀避开 `.idx`/`.vif` + 专项单测 |

## 6. 落地顺序(不改变 M2 的优先级)

1. M2(错误分类 + 重试)——便宜且必要;
2. M3 第一半(T3.1–T3.4):版本保留 + 描述符带代次——**低风险**,单独做也不会产生错误结果,
   只是空间回收变保守;
3. M3 第二半(T3.5–T3.8):引用表 + 回收策略 + 空间回归——真正的难点;
4. M4:用故障注入矩阵验证"老任务不受整理影响"。
