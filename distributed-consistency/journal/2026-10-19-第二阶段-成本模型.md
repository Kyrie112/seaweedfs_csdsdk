## 0. 本次做了什么

1. 建立主机路径与近存路径的线性成本模型;
2. 推导 break-even 判据(比较边际成本,而不是固定开销);
3. 编写拟合脚本 `csd-experiments/scripts/fit_cost_model.py`,从已有的
   图像检索数据(4/16/64 MiB)估计参数;
4. 做敏感性分析,给出"主机在什么条件下会反超"的临界计算速率;
5. 如实记录模型局限(3 个点、主机路径含 Python 计算、共享容器噪声)。

## 1. 拟合结果

```text
T_off(S)  = 8.72 ms + 1.7589 ms/MiB * S
T_host(S) = 0.00 ms + 124.7548 ms/MiB * S
```

- 实测点:4 MiB → 16.49 / 505.50 ms;16 MiB → 35.94 / 1978.68 ms;
  64 MiB → 121.47 / 7988.25 ms(near / host);
- 三点拟合下主机截距为负,已按"固定开销非负"的物理约束截断为 0;
- 在本区间内没有正交叉点:近存路径的边际成本比主机低约 71 倍。

## 2. 关键结论

| 链路 | 主机打平所需计算速率 |
| --- | --- |
| 1 GiB/s | ≈ 1318 MiB/s |
| 5 GiB/s | ≈ 641 MiB/s |
| 10 GiB/s | ≈ 603 MiB/s |

即:**近存的优势来自"链路慢 + 设备快",而不是"存储端一定更快"**。
当主机算子足够快时,大文件上主机路径会反超。
