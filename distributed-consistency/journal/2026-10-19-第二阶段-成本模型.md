## 0. 本次做了什么

1. 建立主机路径与近存路径的线性成本模型;
2. 推导 break-even 判据(比较边际成本,而不是固定开销);
3. 编写拟合脚本 `csd-experiments/scripts/fit_cost_model.py`,从已有的
   图像检索数据(4/16/64 MiB)估计参数;
4. 做敏感性分析,给出"主机在什么条件下会反超"的临界计算速率;
5. 如实记录模型局限(3 个点、主机路径含 Python 计算、共享容器噪声)。

## 1. 拟合结果

```text
T_off(S)  = 8.72 ms + 1.7589 ms/MiB * S
T_host(S) = 0.00 ms + 124.7548 ms/MiB * S
```

- 实测点:4 MiB → 16.49 / 505.50 ms;16 MiB → 35.94 / 1978.68 ms;
  64 MiB → 121.47 / 7988.25 ms(near / host);
- 三点拟合下主机截距为负,已按"固定开销非负"的物理约束截断为 0;
- 在本区间内没有正交叉点:近存路径的边际成本比主机低约 71 倍。

## 2. 关键结论

| 链路 | 主机打平所需计算速率 |
| --- | --- |
| 1 GiB/s | ≈ 1318 MiB/s |
| 5 GiB/s | ≈ 641 MiB/s |
| 10 GiB/s | ≈ 603 MiB/s |

即:**近存的优势来自"链路慢 + 设备快",而不是"存储端一定更快"**。
当主机算子足够快时,大文件上主机路径会反超。

## 5. 交叉点分析补充(2026-10-19)

新增脚本 `csd-experiments/scripts/crossover_analysis.py`,把时延拆成链路、
主机计算、设备读取、设备算子四个分量后比较边际成本:

```text
a_host = 1/B_link + 1/P_host
a_csd  = 1/(k_read*B_dev) + 1/(k_compute*P_dev)
```

实测分量中位数:B_link=321.8 MiB/s, P_host(Python)=8.2 MiB/s,
B_dev/块=164.9 MiB/s, P_dev/块=666.7 MiB/s。

| CSD 形态 | 边际成本(ms/MiB) |
| --- | --- |
| 串行(当前 C++ agent) | 7.56 |
| 并发(软件 agent,k=8) | 0.95 |
| 流水线(读并行、算串行) | 2.26 |

结论:

1. 本实验(Python 主机,125.5 ms/MiB)下 CSD 全面占优;
2. 当主机计算达到 **500 MiB/s** 时,主机反超**串行** CSD(5.11 < 7.56);
3. 但主机要反超**并发/流水线** CSD,需要约 2 GiB/s 计算速率 + 3 GiB/s 链路;
4. **设备侧并发化是把 CSD 优势从 7.56 提升到 0.95–2.26 ms/MiB 的关键**,
   这也解释了为什么当前 C++ agent 的串行处理值得优先优化;
5. 单块文件 k=1,拿不到并行收益——小文件上 CSD 的收益最弱。

适用边界:分量来自本地容器与软件 agent,真机必须重新拟合。
