# M4 可验证:故障注入矩阵与不变量检查

> 目标:把"我们没观察到不一致"升级为"我们验证了不变量成立"。
> 方案依据:[PLAN 第 7 节](../DISTRIBUTED_CONSISTENCY_PLAN.md)。

## 1. 范围与验收

**做什么**

- 可脚本化的故障注入工具(覆盖 F1–F7);
- **不变量检查器**:自动判定结果是否属于某个单一快照;
- 执行矩阵、归档数据、形成结论;
- 回填论文第 4/6 章。

**出口条件**

| 判据 | 标准 |
| --- | --- |
| 覆盖 | F1–F7 每一行都有明确结论(通过/失败/不适用) |
| 静默错误 | **静默错误计数 = 0** |
| 可复现 | 任一结论都能由一条命令重新产出 |

## 2. 故障矩阵(与本目录共用)

| 编号 | 注入场景 | L1 期望 | L2 期望 |
| --- | --- | --- | --- |
| F1 | 计算期间覆盖写同一文件 | 每块同版本,不混用 | 全块同版本,否则重试/失败 |
| F2 | 计算期间删除文件 | 显式失败或降级 | 同左 |
| F3 | 计算期间对卷做整理(vacuum) | 自校验触发 `stale_range`,重试或显式失败 | 同左 |
| F4 | needle 过期后区间被新写入复用 | cookie 校验失败,不返回结果 | 同左 |
| F5 | 模拟一个副本滞后 | 允许(单块自洽) | **必须**检出,不返回混版结果 |
| F6 | 新旧内核/协议并存 | 语义按版本回退,结果一致 | 同左 |
| F7 | 计算期间部分块节点宕机 | 排除集重试到其他副本 | 同左 |

## 3. 步骤

### T4.1 故障注入工具

- **目标**:让 F1–F7 可一键触发、可重复;
- **前置**:M1、M2 完成;
- **改动**:`csd-experiments/scripts/`(新增 `fault_injection.sh` / `fault_lib.py`);
- **关键流程**:
  1. 复用现有部署脚本(起 master/volume/filer/agent);
  2. 为每类故障实现一个注入原语:
     覆盖写、删除、触发整理、区间复用(写满再用)、副本滞后(软件 agent 返回旧版本)、
     版本错配(加载旧内核语义)、节点宕机(杀进程);
  3. 每个原语接受"注入时机"参数(计算前 / 计算中 / 计算后),以便覆盖不同窗口;
  4. 注入与请求并发执行,记录时间线;
- **验证与通过标准**:每类故障都能被稳定触发(重复 5 次均生效);
- **产出**:注入工具与用法说明;
- **回滚**:工具独立于被测系统,无回滚问题;
- **风险**:注入必须作用于**被测系统的真实路径**(例如真的做一次 vacuum),而不是打桩模拟,
  否则结论不可信。

### T4.2 不变量检查器

- **目标**:把"结果是否正确"变成机器可判的二值结论;
- **前置**:T4.1;
- **改动**:同上;
- **关键流程**:
  1. 在注入前/后各保存一份**一致快照**(复制数据文件或固定版本),分别计算结果 `R_A`、`R_B`;
  2. 判定:请求失败 → PASS;结果 ∈ {R_A, R_B} → PASS;否则 → **FAIL(静默错误)**;
  3. 输出结构化结果(CSV):场景、注入时机、期望、实际、判定、耗时;
- **验证与通过标准**:对"人为构造的混版结果"能判定为 FAIL(用反例自测检查器本身);
- **产出**:检查器 + 自测;
- **回滚**:—
- **风险**:检查器自身必须先用**已知错误**验证过,否则"全 PASS"没有说服力。

### T4.3 执行 F1–F7 矩阵

- **目标**:产出完整的一致性结论表;
- **前置**:T4.1、T4.2;
- **改动**:实验脚本与结果目录;
- **关键流程**:逐行执行,每行重复不少于 5 次,记录判定分布;
- **验证与通过标准**:每行有结论;静默错误计数为 0;若出现 FAIL,需定位并回到相应里程碑修复;
- **产出**:`csd-experiments/results/consistency_matrix.csv` 与汇总;
- **回滚**:—
- **风险**:部分场景(如 F6 灰度升级)难以在本机复现,需说明复现条件或标记为受限。

### T4.4 一致性报告

- **目标**:把数据与结论写成可引用的报告;
- **前置**:T4.3;
- **改动**:`csd-experiments/reports/REPORT_CONSISTENCY.md`(新增);
- **关键流程**:报告包含:方案回顾、矩阵结果、代价数据(时延/吞吐)、未覆盖场景、结论与适用边界;
- **验证与通过标准**:报告中的每个数字都能在结果 CSV 中找到来源;
- **产出**:报告;
- **回滚**:—
- **风险**:避免只报正面结论;失败与限制必须同表列出。

### T4.5 回填论文

- **目标**:使论文包含"一致性"这一完整章节;
- **前置**:T4.4;
- **改动**:`csd-experiments/reports/THESIS_DRAFT.md`;
- **关键流程**:
  1. 第 4 章增加"一致性与正确性"小节(不变量、快照令牌、设备自校验的设计与取舍);
  2. 第 6 章增加一致性实验小节(矩阵结果与代价);
  3. 摘要与结论同步更新;
- **验证与通过标准**:图表编号连续、数据与报告一致、无未标注的推测性表述;
- **产出**:论文修订;
- **回滚**:—
- **风险**:若矩阵存在未通过项,论文必须如实描述为"已知限制"而非省略。
