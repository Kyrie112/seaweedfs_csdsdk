# M2 可规避:副本一致性与失败语义

> 目标:处理 **C4(副本滞后导致跨块混版)** 与 **C1(元数据 TOCTOU)**,
> 并把"数据已变"从"请求失败"转化为"重试一次"。
> 方案依据:[PLAN 第 5.3、5.7 节](../DISTRIBUTED_CONSISTENCY_PLAN.md)。

## 1. 范围与验收

**做什么**

- 请求级副本亲和:同一次请求尽量使用同一组副本;
- 副本回报本地数据版本,Filer 做同请求一致性校验(L2);
- `stale_range` 的显式重试策略;
- 错误分类与一致性等级 API。

**不做什么**:不实现卷代次/读租约(M3);不改复制协议本身。

**出口条件**

| 判据 | 标准 |
| --- | --- |
| 混版 | 模拟一个副本滞后时,L2 请求**不返回混版结果** |
| 重试 | `stale_range` 触发后能重新解析清单并成功,不产生活锁 |
| 可观测 | 三类重试原因可从 `X-Compute-Retry-Reason` 区分 |
| 回归 | 既有全部用例 + 实验台功能实验通过 |

## 2. 步骤

### T2.1 请求级副本亲和

- **目标**:降低"同请求不同块来自不同复制进度副本"的概率;
- **前置**:M1 完成;
- **改动**:`weed/server/filer_csd_scheduler.go`、`filer_csd_scheduler_rank.go`;
- **关键流程**:
  1. 在请求上下文里维护一个"本请求已使用的副本集合";
  2. `rankAndReserve` 排序时,对已在集合内的副本给予优先级(作为目标函数的一个新次级键,
     放在 CSD 能力之后、负载之前或之后需实测决定);
  3. 集合内副本全部不可用时才回退到集合外,并记录一次"亲和失败";
- **验证与通过标准**:构造 3 副本场景,统计同请求副本集合大小分布(期望从 3 收敛到 1–2);
- **产出**:调度改动 + 统计;
- **回滚**:revert;调度目标是软的,不影响正确性;
- **风险**:过度亲和会削弱负载均衡,必须同时测"负载分布"是否退化。

### T2.2 副本版本回传与校验

- **目标**:让 Filer 能判断"各块是否来自同一代数据";
- **前置**:T2.1;
- **改动**:`weed/server/filer_compute_aggregation.go`、`csd_compute.go`(回传)、
  `smartssd/src/csd_agent.cpp`(返回版本字段);
- **关键流程**:
  1. 设备/volume 在响应中回传本地数据版本(建议:needle `LastModified` + 卷数据文件标识);
  2. Filer 聚合前收集各块版本;
  3. L2 下:版本集合大小 > 1 → 触发重试或失败(策略由 `on_stale` 参数决定);
  4. L1 下:仅打标 `X-Compute-Consistency-Level`,不阻塞;
- **验证与通过标准**:单测构造"两块版本不同"的假响应,断言 L2 拒绝、L1 打标;
- **产出**:版本回传与校验;
- **回滚**:revert;
- **风险**:版本字段必须**单调可比**;若某后端无法提供,需明确降级为"不可判定"而非误判一致。

### T2.3 `stale_range` 重试策略

- **目标**:把一致性冲突转化为一次重试,而不是让业务失败;
- **前置**:T1.4;
- **改动**:`weed/server/filer_server_handlers_proxy.go`、`filer_csd_scheduler_rank.go`;
- **关键流程**:
  1. 重试循环中区分三类失败:`node_error`(换副本即可)、
     `stale_range`(需**重新解析清单**)、`unsupported_format`(直接降级);
  2. `stale_range` 时:重新读取 filer 条目 → 重新展开清单 → 重新生成令牌 → 重试;
  3. 限定重试次数(建议 1 次),并在响应头记录 `X-Compute-Retry-Reason`;
  4. 与现有排除集配合,避免在同一个已过期副本上反复重试;
- **验证与通过标准**:
  - 注入 F1/F2/F3 场景,期望"要么成功(重试后一致)、要么显式失败";
  - 断言重试次数不超过上限(不活锁);
- **产出**:重试策略 + 注入实验数据;
- **回滚**:revert 到"直接失败";
- **风险**:重试会放大负载,需与扇出并发上限(8)和每主机上限(16)联动评估(Q4)。

### T2.4 错误分类与响应表达

- **目标**:让调用方与运维能区分"数据变了""节点坏了""格式不支持";
- **前置**:T2.3;
- **改动**:`csd_compute.go`、`filer_server_handlers_proxy.go`;
- **关键流程**:
  1. 定义四类错误码:`not_found` / `stale_range` / `node_error` / `unsupported_format`;
  2. 统一在响应头与错误体中表达;
  3. 降级到脚本路径时标注 `X-Compute-Path: script`,避免调用方误以为走了近存路径(Q5);
- **验证与通过标准**:四类错误可分别构造并通过响应头识别;
- **产出**:错误分类与响应;
- **回滚**:revert;
- **风险**:错误码对外可见,需在 API 文档中登记,避免后续随意变更。

### T2.5 一致性等级 API

- **目标**:让调用方按需选择语义,而不是系统单方面决定;
- **前置**:T2.2;
- **改动**:`weed/server/filer_compute_api.go`、`filer_server_handlers_read.go`;
- **关键流程**:
  1. 支持 `?compute=<op>&consistency=L0|L1|L2&on_stale=retry|fail`;
  2. 缺省行为 = L1 + retry,保证向后兼容;
  3. 响应回传实际达到的等级与快照摘要;
  4. 更新 API 文档与示例;
- **验证与通过标准**:三档在同一故障场景下行为差异可复现(形成一张对照表);
- **产出**:API 扩展 + 对照表;
- **回滚**:revert;缺省行为不变;
- **风险**:L2 会引入额外校验与重试,需在文档中明确其代价。

### T2.6 一致性单元测试与端到端

- **目标**:把 M2 的语义固化为可回归测试;
- **前置**:T2.1–T2.5;
- **改动**:`weed/server/*_test.go`、实验台脚本;
- **关键流程**:
  1. 单测:副本亲和收敛、版本不一致检出、重试上限、四类错误码;
  2. 端到端:用实验台构造"一个副本滞后"(软件 agent 支持人为返回旧版本),验证 L2 行为;
- **验证与通过标准**:全部通过,且"静默错误"计数为 0;
- **产出**:测试与数据;
- **回滚**:revert;
- **风险**:需要软件 agent 支持"扮演滞后副本",该项应在 T1.6 的故障注入开关中一并设计。

## 3. 决策门 D2

M2 结束时回答:**请求级亲和是否已足以覆盖混版风险?**

- 若试验表明"同请求副本集合已收敛且版本校验很少触发" → M3 可标记 ➖ 不适用;
- 若仍频繁触发 → 说明需要更强的机制,继续 M3。
