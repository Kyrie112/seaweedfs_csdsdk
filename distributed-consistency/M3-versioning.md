# M3 版本化快照与延迟回收(核心机制)

> 目标:让"计算期间数据被改写"**不再导致失败**——老任务读老版本,新写入追加为新版本,
> 版本在没有请求引用它之后回收。即多版本并发控制(MVCC)加延迟回收。
> 方案依据:[PLAN 第 5.4 节](../DISTRIBUTED_CONSISTENCY_PLAN.md)。
>
> **本里程碑是当前方案的核心机制**,不再是原来的"可选档"。
> M1(可检测)由主路径退化为**兜底路径**:仅在强制回收或引用丢失时触发显式失败。

## 1. 设计要点回顾

| 维度 | 内容 |
| --- | --- |
| 版本单位 | 卷数据文件(compaction 的一次提交 = 一个代次) |
| 老任务如何读老版本 | 描述符直接携带**该代次的文件路径** + offset/size + cookie,不再依赖当前索引 |
| 新写入 | 天然追加(SeaweedFS 覆盖写 = 新 needle + 索引切换),无需改造 |
| 回收条件 | 引用归零 **且** 年龄超过宽限期 **且** 未触发保险上限 |
| 谁持有引用 | **Filer**(唯一掌握请求完整生命周期的组件),带 TTL 与心跳 |
| 谁执行回收 | Volume(它拥有文件),依据 Filer 发布的引用状态 |
| 兜底 | 强制回收 / Filer 重启丢引用 → 回到 M1 的 `stale_range` 显式失败 |

**关键前提(已核实)**:`weed/storage/disk_location.go` 的 `isValidVolume()`
只认 `.idx` / `.vif` 结尾的文件,因此 `3.dat.g7` 这类带代次后缀的文件
**不会被卷扫描认领**;版本文件对其它子系统不可见,仅 CSD 计算路径可寻址。

## 2. 要改的地方(已核实的位置)

`weed/storage/volume_vacuum.go` 的提交阶段在写锁内执行(约 269–283 行):

```go
os.RemoveAll(v.FileName(".dat"))                    // 直接删除在线数据文件
os.Rename(v.FileName(".cpd"), v.FileName(".dat"))   // 用整理副本替换
...                                                 // .idx 同理
```

本里程碑要把这段改成 **"旧文件改名保留 + 新文件提交 + 登记代次"**,
并接入既有的崩溃恢复流程(`.cpc` 标记 + `disk_location.go:reconcileCompactStates`)。

## 3. 步骤

### T3.1 卷数据文件代次(基础)

- **目标**:给"数据文件被替换"一个可传递、单调递增的编号;
- **改动**:`weed/storage/volume.go`、`weed/storage/volume_vacuum.go`;
- **关键流程**:
  1. 卷对象上增加原子访问的 `dataGeneration uint64`;
  2. 仅在**替换临界区**内自增——该临界区已持有 `dataFileAccessLock` 写锁,
     不需要新锁;
  3. 提供并发安全的读取接口,供描述符构造与回收器使用;
  4. 启动加载卷时,从现存的最高代次恢复(避免重启后代次回退导致误判);
- **验证**:单测模拟多次整理,断言代次严格递增、并发下无回退(race detector);
- **回滚**:revert;新字段不影响既有行为;
- **风险**:代次恢复逻辑必须与磁盘上现存版本文件一致,否则重启后可能复用旧代次号。

### T3.2 版本化文件布局

- **目标**:让旧版本在磁盘上"继续存在且可被精确寻址";
- **改动**:`weed/storage/volume.go`(命名)、`weed/storage/disk_location.go`(可见性);
- **关键流程**:
  1. 约定版本文件命名:`<base>.dat.g<代次>` 与 `<base>.idx.g<代次>`;
  2. **后缀不得是 `.idx` / `.vif`**,否则会被 `isValidVolume()` 当成新卷加载;
  3. 版本文件不参与卷加载、备份与复制;仅 CSD 计算路径通过描述符中的路径访问;
  4. 提供"枚举某卷的全部版本文件"的内部接口,供回收器使用;
- **验证**:单测:在卷目录放入 `3.dat.g7` 后重启 store,断言它**未被加载为新卷**,
  且卷 3 正常可用;
- **回滚**:删除版本文件、revert 命名逻辑;
- **风险**:若目录同时配置了 `.idx` 目录,命名与可见性规则需在两处保持一致。

### T3.3 整理改造:保留而非删除

- **目标**:把 compaction 从"替换"改成"保留旧版本 + 提交新版本";
- **前置**:T3.1、T3.2;
- **改动**:`weed/storage/volume_vacuum.go`(`CommitCompact` 与恢复路径);
- **关键流程**:
  1. 提交前:把当前 `.dat` / `.idx` **改名**为对应代次的版本文件(而非删除);
  2. 提交:把 `.cpd` / `.cpx` 改名到 `.dat` / `.idx`(保持既有顺序与 fsync);
  3. 代次自增,并把"新代次 → 当前文件"的映射登记到回收器;
  4. **崩溃恢复**:`.cpc` 标记与 `reconcileCompactStates` 必须能处理
     "已改名但未提交"的中间状态——要么完成提交,要么回滚改名;
  5. 版本文件登记成功之前不得删除任何东西;
- **验证**:
  - 单测:模拟整理过程中崩溃(注入 rename 之间的失败),断言重启后卷可用且版本可回收;
  - 集成:整理与计算并发时,在途请求全部成功;
- **回滚**:revert 到"删除 + 替换";版本文件可手工清理;
- **风险**:**这是本里程碑风险最高的一步**——它改动了数据文件的提交路径,
  必须保持既有的崩溃安全保证(现有代码对"只完成 .dat 改名"的中间态有专门处理)。

### T3.4 描述符携带代次

- **目标**:让老请求精确指向老版本文件;
- **前置**:T3.3;
- **改动**:`weed/storage/volume_read.go`、`weed/server/csd_compute.go`;
- **关键流程**:
  1. `NeedleComputeRegion.DataFile` 填入**该代次**的路径(当前代次 = 在线文件);
  2. M1 已有的 cookie / needle id / 长度校验保持生效,作为二次确认;
  3. 协议无需新增字段(路径本身已经承载了版本信息);
- **验证**:整理前后分别发起请求,断言两者各自成功且结果分别对应各自版本的数据;
- **回滚**:revert;
- **风险**:描述符里的路径属于对外可见的协议内容,命名规则一旦发布不宜再改。

### T3.5 引用 / 租约注册表

- **目标**:知道"哪些版本正在被哪些请求使用";
- **前置**:T3.4;
- **改动**:`weed/server/filer_compute_consistency.go`、`filer_server_handlers_proxy.go`;
- **关键流程**:
  1. Filer 在请求开始(生成快照令牌时)登记引用:`{卷, 代次, 请求 ID, 过期时间}`;
  2. 每个块完成后续租(心跳);请求结束(成功或失败)时释放;
  3. 租约带**强制上限**(如 5 分钟),超时自动释放并记录事件;
  4. 引用状态需要能被 Volume 查询:优先复用现有的状态通道;若跨节点,
     考虑由 Filer 主动推送"可回收代次"列表;
- **验证**:单测覆盖"登记 → 续租 → 释放""超时自动释放""Filer 重启后引用表为空";
- **回滚**:revert 到 TTL-only 的保守回收(见 T3.6);
- **风险**:Filer 重启会丢失内存引用表——这是本方案最薄弱的一环,
  必须有 TTL + 宽限期兜底,并考虑持久化。

### T3.6 回收策略与保险

- **目标**:在不影响在途请求的前提下把空间收回来;
- **前置**:T3.5;
- **改动**:`weed/storage/volume_vacuum.go` 或新增 GC 组件;
- **关键流程**:
  1. 回收条件:`引用为空` ∧ `年龄 > 宽限期(默认建议 10 分钟)` ∧ `不是当前代次`;
  2. 三道保险:单卷版本数上限(如 4)、单卷版本占用空间上限、磁盘压力兜底;
  3. 触发保险时**提前回收**并记录 `forced_reclaim` 事件——此后仍未完成的请求
     会退化为 M1 的 `stale_range` 显式失败;
  4. 回收最小单位是"一次整理的整份旧文件",不做文件内逐 needle 回收(实现简单、风险低);
- **验证**:
  - 单测:三条回收路径(正常 / 版本数上限 / 磁盘压力)各自行为正确;
  - 集成:无引用时旧版本被回收,空间回到基线;
- **回滚**:提高宽限期或关闭保留下限即可;
- **风险**:宽限期过长会放大空间占用,过短则失去意义;需要 T3.8 的实测数据定标。

### T3.7 与 M1/M2 的配合

- **目标**:保证异常路径下仍然不出现静默错误;
- **前置**:T3.6;
- **改动**:`weed/server/csd_compute.go`;
- **关键流程**:
  1. 强制回收、引用丢失、代次不匹配等场景一律走 M1 的 `stale_range`;
  2. M2 的错误分类与重试策略接管后续处理(重新解析清单 → 重试);
  3. 响应中标注本次请求的版本与是否发生回收(可观测);
- **验证**:构造"引用被强制回收"的场景,断言请求显式失败而非返回错误结果;
- **回滚**:—
- **风险**:必须避免"重试仍读到同一被回收版本"的活循环(由 M2 的排除集保证)。

### T3.8 空间与性能回归

- **目标**:给出"是否默认开启、宽限期取多少"的数据依据;
- **前置**:T3.1–T3.7;
- **改动**:存储层测试 + `csd-experiments/scripts/`;
- **关键流程**:
  1. 构造"持续覆盖写 + 持续计算"的混合负载,记录:
     同时存活版本数、额外占用的磁盘空间、整理吞吐、GC 延迟;
  2. 改变宽限期与覆盖频率,得到空间放大随参数变化的曲线;
  3. 给出默认参数建议与"是否默认启用"的结论;
- **验证与通过标准**:空间放大与整理吞吐回归落在约定预算内(预算在开工前确定);
- **回滚**:参数可调;极端情况下关闭版本保留,退回 M1 兜底;
- **风险**:空间放大在"大文件 + 高频覆盖"下可能很显著,必须如实报告。

## 4. 验收标准(里程碑出口)

| 判据 | 标准 |
| --- | --- |
| 在途请求不受整理影响 | 整理与计算并发时,在途请求**全部成功**,且结果对应其开始时的版本 |
| 版本可回收 | 无引用且超过宽限期后,旧版本被回收,空间回到基线 |
| 异常路径无静默错误 | 强制回收 / Filer 重启等场景退化为 `stale_range` 显式失败 |
| 版本文件不污染卷管理 | 重启后版本文件不被加载为卷,卷功能正常 |
| 崩溃安全 | 在改名/提交的任意中间态崩溃,重启后卷可用且版本可回收 |
| 代价可控 | 空间放大与整理吞吐回归在 T3.8 约定预算内 |

## 5. 风险汇总

| 编号 | 风险 | 缓解 | 归属 |
| --- | --- | --- | --- |
| V1 | Filer 重启丢引用 → 误回收 | TTL + 宽限期 + 保守回收条件;考虑持久化 | T3.5 |
| V2 | 长尾请求占用旧版本 | 租约强制上限 + 强制回收 + M1 兜底 | T3.5 / T3.6 |
| V3 | 空间放大 | 版本数/空间上限、磁盘压力兜底、参数可调 | T3.6 / T3.8 |
| V4 | 崩溃恢复复杂化 | 复用 `.cpc` 标记流程;改名与提交均保持原子序 | T3.3 |
| V5 | 版本文件污染卷管理 | 命名后缀避开 `.idx`/`.vif`;T3.2 专项单测 | T3.2 |
| V6 | 其它子系统(备份/复制/EC)误处理版本文件 | 明确不可见性并加断言/测试 | T3.2 |

## 6. 决策门 D3

M3 结束时回答两个问题:

1. **空间放大是否可接受?** 若不可接受 → 缩短宽限期,或改为按需开启(仅长任务算子);
2. **是否默认启用版本保留?** 默认启用最安全;若空间压力大,可退化为
   "默认关闭 + 对超过阈值时长的请求动态开启"。
